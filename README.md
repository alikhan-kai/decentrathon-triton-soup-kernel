## Mechanisms and attribution

| Module | Change | Original-kernel credit |
|---|---|---|
| `head_loss.py` | Fuse loss, entropy and accuracy over 256-row logits chunks; retain at most 128 MiB of labelled FP16 logits, then recompute the remaining backward projection | `head_loss_kernel`, `_cache_labelled_logits` |
| `nf4.py` | Fuse nested double-quantized NF4 unpacking before the existing FP16 matrix multiplication | `nf4_dequant_kernel` |
| `rmsnorm.py` | Fuse FP32 RMS normalization forward and input-gradient reductions | `rmsnorm_fwd_kernel`, `rmsnorm_bwd_kernel` |
| `rotary.py` | Joint Q/K split-half rotation with explicit reference rounding | `ember_rope_joint`; device helper is not separately credited |
| `packed.py`, attention adapters | Remove padding inside each original batch; use native variable-length FP16 attention with separate example boundaries and shared QKV casts | None: native PyTorch operators |
| `swiglu_pack.py`, MLP adapters | Fused frozen MLP autograd, shared casts, budgeted activation saves and rematerialization | None: starter SwiGLU is excluded |
| `frozen_weight.py` | Store tied frozen embedding/head in FP16 only after exact FP32 round-trip verification | None |
| `overhead.py`, `lazy_bnb_compile.py` | Reuse process-local metadata and dataset mapping; defer four pinned BNB decorator constructions until actually called, preserving compiler flags and fallback behavior | None: generated dependency kernels are excluded |
| `precompile.py` | Compile the actual specializations on one thread inside the timed process while model loading proceeds | None: no extra process or cache from an earlier run |

The head-chunking idea comes from [Soup's stream_loss_chunk](https://github.com/MakazhanAlpamys/Soup/blob/main/src/soup_cli/utils/stream_loss_chunk.py). NF4 layout follows [QLoRA](https://arxiv.org/abs/2305.14314) and bitsandbytes 0.50.2. RMSNorm, RoPE, SDPA and LoRA semantics follow Transformers 5.16.1 and PEFT 0.20.0. Starter `example_swiglu_*` and kernels generated by `torch.compile` receive zero original-kernel credit. Repository code and starter kit retain [Apache-2.0 licensing](LICENSE) and [NOTICE](NOTICE).

## Refinement for the official rules

The earlier H20 import guard explicitly opened installed bitsandbytes Python source to hash it. This refinement removes those source reads and validates the real loader, package version, function identity, active decorator frame, options and importing thread instead. The actual dependency function bodies, compiler options and fallback protocol remain unchanged. Only this import guard and its tests changed; the head module's obsolete draft comment was also removed.

On the Kaggle T4, `pytest -q solution` completed with **504 passed / 147 skipped**. The isolated fresh-import test passed separately; its combined-suite skip prevents a previously imported BNB module from invalidating the fresh-import precondition. CPU protocol tests also passed. `tools/lint_rules.py solution` reports **44 files, 11 kernels, zero problems**. Skipped tests are not counted as passes. Automatic checks do not replace the judges' source review.

Use [ember-judge-ready-final.ipynb](ember-judge-ready-final.ipynb), a copy of the unchanged organizer template with the exact runtime SHA and recorded dependencies pinned. The notebook has no saved result outputs; the measured outputs are in the evidence archive. A public saved Kaggle version still needs to be created. The existing research notebook is [ember-score-validation-20261031](https://www.kaggle.com/code/tukhtakhunovamir/ember-score-validation-20261031).

Environment: Python 3.13, Tesla T4, PyTorch 2.11.0+cu128, Triton 3.6.0. Use one GPU and leave both devices idle before starting; the unchanged harness isolates GPU 0. Internet is needed for model/data setup. Installation happens outside the timed training process.

```bash
git clone https://github.com/alikhan-kai/decentrathon.git
cd decentrathon
git checkout c580bf8ae53c24b0d4fa08e4d64b08936e3ac1f6
python -m pip uninstall -y torchao

python task/prepare_data.py
python -m pytest -q solution/test_lazy_import.py
python -m pytest -q solution
python harness/run_task.py --repeats 2 --out runs
python harness/check_rules.py --result runs/result.json
python harness/score.py runs/result.json
```

`torchao` is a prohibited/preinstalled optional package and is removed during setup; no package installation or removal happens inside measured runs. The checked-in organizer files under `harness/`, `task/`, `tests/` and `templates/` are unchanged.

## Timing variability and limitations

- This is a workload-specific FP16 T4 path with guards and upstream fallbacks; unsupported layouts, hooks and higher-order gradients are not accelerated.
- The earlier H20 single screen of **45.94 s / 3065 MiB** was not a complete repeated validation. H20 full measurements were **52.62 s** previously and **51.59 s** in this fresh session. Do not advertise the single screen as repeatable full timing.
- H21's 512-row forward-chunk experiment completed a separate full run at **47.67 s / 3145 MiB** (47.59 and 47.74), but its same-session screening improvement over H20 was only 0.26 s for 80 MiB extra. It was not promoted. H16's older full run was 46.05 s / 3325 MiB and later controls slowed above 51 s. Different session timings are not controlled speed comparisons.
- No repeatable sub-40 s result is claimed. The current host has not demonstrated a repeatable sub-50 s result for the selected 3065 MiB code.
- The predetermined public holdout replay (rows 1000–1255, eval 41000–41255, seed 17) is recorded in the audit ledger. Do not treat it as completed unless its result and checks are present in the archive. It is not the judges' hidden data.
- Padding removal can change dropout RNG consumption; the full curves, token/entropy/accuracy metrics, rewind records and evaluation remain within the official gates on the measured public data. Hidden-row results cannot be guaranteed.
